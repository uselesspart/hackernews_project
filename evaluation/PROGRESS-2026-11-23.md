# Команда 6: состояние проекта на 23 ноября 2026 года

Цель текущего этапа — локальная демонстрация на презентации. Публичный хостинг,
домен, серверный деплой и CD исключены из текущего объёма по решению владельца.
Этот документ дополняет недельные отчёты, не меняя их задним числом.

## Что выполнено

- Недельные ряды доли упоминаний: знаменатель — все живые статьи с заголовком,
  включая статьи без технологий. Неполные крайние недели исключены, пропуски
  внутри периода не подменяются нулями интереса.
- Прогноз на одну неделю: последнее значение, среднее за четыре недели, лаг четыре
  недели и Ridge с четырьмя коэффициентами регуляризации. Скейлер и модель учатся
  только на предшествующих наблюдениях. Метод выбирается на validation и фиксируется
  до test; во время пошагового test история пополняется уже наблюдёнными неделями.
  Это прогноз с горизонтом одна неделя, а не прогноз сразу на весь тестовый отрезок.
- Для допуска к эксперименту нужны 16 полных недель и минимум 30 упоминаний
  в первоначальной обучающей части, до validation и test. На текущей базе доступны
  **38 технологий**; у **15** выбранный метод обошёл последнее значение на test.
  Тест содержит всего четыре недели. Это ограниченный эксперимент, не подтверждение
  способности предсказывать текущую популярность.
- Добавлены `/api/techs/{key}/forecast` и блок прогноза на странице технологии:
  период, ожидаемая доля, ошибка и сравнение с базовым прогнозом. Архивные данные
  явно обозначены. Последняя полная неделя заканчивается 4 августа 2024 года,
  целевая неделя начинается 5 августа 2024 года.
- Проверен обучаемый классификатор TF-IDF слов и символьных n-грамм + LinearSVC.
  C и порог VADER выбираются только на validation. Test macro-F1 общего тона:
  **SVM 0,404, VADER 0,603**. Отношение к технологии: **SVM 0,324, VADER 0,379**.
  SVM не заменяет текущий VADER в сервисе. Все эти метрики — относительно AI-меток.
- Разобран bootstrap на 3 000 независимых обучающих строках: из 600 уверенных
  псевдометок **449 положительных, 151 отрицательная и ни одной нейтральной**.
  Такой классификатор не может предсказывать нейтральный класс. Нулевых векторов
  всего 6 из 3 000; одной лишь вырожденностью векторов слабый результат не объясняется.
- IRR проверен в восьми вариантах, включая месяц, день недели и циклический час UTC.
  Во всех вариантах модель сошлась. Для Windows IRR с календарными контролями
  **2,216 [1,543; 3,184]**, BH q-value **0,000712**. В исходной полной модели
  после BH FDR 5% значима **1 технология вместо 5** по отдельным p-value.
  BH применяется только к коэффициентам технологий, без контролей и взаимодействий.
  API и интерфейс различают отдельный 95% интервал и результат множественной проверки.
- Выполнен аудит всех 102 технологий модели контекста. Для 31 редкой технологии
  (токен встречается меньше 20 раз) доля соседей из общей категории — **0,248**,
  для остальных 71 — **0,597**. Это диагностический прокси, не человеческая оценка
  релевантности. Сохранён список соседей для проверки человеком.
- Подготовлена новая независимая выборка: **600 заголовков** (200 development,
  400 holdout) и **101 длинный комментарий из 89 статей**, 651–5000 символов.
  Исключены 1 760 статей предыдущих выборок и обучения bootstrap. Метки оставлены
  пустыми; разделение комментариев по статьям зафиксировано. Старые 400 заголовков
  и замороженный словарь не использованы для подбора новых правил.
- Подготовлены слепая проверка прежних 315 комментариев и импорт человеческих меток.
  Импорт проверяет текст, технологию, split, имя проверяющего и дату; непроверенные
  AI-метки не попадают в человеческий эталон. Пустое отношение не заменяется нейтральным.
- Стандартное обучение Word2Vec переведено на 50 измерений, 20 эпох, seed 42,
  один поток; имена моделей в Bash/BAT согласованы с настройками.
- Добавлены сравнение двух-трёх технологий, интерактивная карта с переходами и
  фильтрация каталога по категориям. Малообеспеченные оценки в сравнении скрыты.
- Добавлены ограниченное инкрементальное обновление и обновление недавних элементов.
  Сбой загрузки останавливает пакет до импорта. Модели при обновлении переиспользуются.
- Локальный показ обслуживается одним процессом Uvicorn: API и собранный React.
  Проверка готовности не создаёт пустую базу. Добавлена конфигурация CI для Python
  и фронтенда; её выполнение на GitHub требует отправки изменений в репозиторий.

## Повторение экспериментов

Из корня проекта, используя установленное окружение:

```powershell
python -m scripts.forecast --db sqlite:///artifacts/study/hn.db --write-db
python -m scripts.evaluate_supervised_sentiment
python -m scripts.engagement_stability --db sqlite:///artifacts/study/hn.db --output-dir artifacts/engagement_v2
python -m scripts.audit_embeddings --model artifacts/study/models/context.model --output-dir artifacts/embeddings_audit
python -m scripts.audit_bootstrap --training artifacts/week07/sentiment_training.csv --titles-model artifacts/study/models/titles.model --context-model artifacts/study/models/context.model
python -m scripts.human_review prepare --output-dir evaluation/human_review
```

Результаты находятся в игнорируемой `artifacts/`; исходные данные для новой ручной
проверки и её инструкция — в `evaluation/next_review/` и `evaluation/HUMAN_REVIEW.md`.
Для воспроизводимости обучения эмбеддингов без пересечений со старыми оценками
используйте `scripts.train_study_models --exclude ...`, как описано в README оценки.
Обычный `train_model` на экспортированном корпусе не знает идентификаторов статей
и самостоятельно не исключает контрольные обсуждения.

Обновление данных требует сети и выполняется вручную перед новым анализом,
а не автоматически при запуске презентации:

```powershell
python -m scripts.update_data --db sqlite:///artifacts/study/hn.db --max-items 5000 --dry-run
python -m scripts.update_data --db sqlite:///artifacts/study/hn.db --max-items 5000 --context-model artifacts/study/models/context.model
```

Одна команда скачивает ограниченный пакет от последнего сохранённого ID, а не
мгновенно переносит архивную базу в 2026 год. Сохраняйте исходный снимок для
презентации. Подготовленные прогнозы относятся к историческому периоду.

## Что остаётся открытым

Проверки текущей реализации: **394 Python-теста, 34 теста компонентов фронтенда,
24 браузерных сценария** на настольном и мобильном экране, включая axe-проверки.
Ruff, TypeScript и production-сборка проходят. В браузерной проверке найдена и
исправлена переполнявшая узкий экран сетка страницы технологии; переходы к соседям
теперь проходят и на мобильном экране.

1. Реальная независимая человеческая разметка и повторная оценка на ней.
2. Следующая версия словаря после разметки новой development-части; затем единственная
   итоговая проверка на новом holdout. Повышение recall пока не заявляется.
3. Более длинная история и новые периоды для проверки прогноза. Точечные прогнозы
   не имеют откалиброванных интервалов, а четыре тестовые недели недостаточны для
   утверждений об устойчивом преимуществе модели.
4. Улучшение аспектной тональности и bootstrap после появления более надёжных меток.
5. Независимая человеческая проверка соседей Word2Vec, особенно редких технологий.
6. Остальной технический долг: полноценные миграции Alembic, тесты PostgreSQL,
   упаковка Python-проекта и оптимизация загрузки моделей. Для локального показа
   это не является обязательным условием.

Календарные контроли и BH не устраняют смешение по тематике, видимости и аудитории.
Ни один результат IRR не следует описывать как причинный эффект технологии.
